# Research Report: Emby / TMDB 命名规范与成熟工具实践对齐

## 0. 研究范围与目标

**范围**

* Emby 官方：电影/剧集命名、Specials/Extras、多版本（Multi-version）、字幕文件命名
* TMDB 官方：API 获取元数据、合集（Collection）识别基础能力
* 成熟工具/实现：FileBot（命名表达式/实践）、tinyMediaManager（季/特别篇处理）、Emby.Naming（Emby/MediaBrowser 的命名解析库）

**目标**

* 抽取“Emby 最稳识别”的落盘命名与目录结构共识
* 覆盖：电影、剧集、动画/OVA/SP、字幕/多语言、多版本、合集（collection）结构归类
* 为你的项目提供“可对齐的标准基线”（而非重写实现）

---

## 1. Emby 官方：电影命名（Movie Naming）

### 1.1 最稳基线：`Title (Year)` 结构

Emby 官方电影命名指南明确推荐的基础格式为：`MovieName (year).extension`，并以“每部电影独立文件夹”作为常见结构示例。 ([Emby][1])

### 1.2 ID Tags：支持在名称里嵌入元数据 ID（含 tmdbid）

Emby 支持从文件夹/文件名中读取元数据 ID，并列出多种格式（如 `[tmdbid=xxxx]` / `{tmdb=xxxx}` 等），支持的 ID 包含 tmdb、imdb、tvdb。 ([Emby][2])

> **对你的项目价值**：当“标题/年份”模糊时，把 `tmdbid` 写入目录名能显著提升识别确定性（尤其是重名作品）。

### 1.3 多版本电影（Multi-version movies）

Emby 官方规定：**同一内容的多个版本必须放在同一电影文件夹中**；每个版本文件名必须以文件夹名开头，并使用 `" - "` 作为分隔，破折号后内容会作为客户端版本选择器的显示名；版本数显示有上限（最多 8）。 ([Emby][2])

> **工程含义**：你无需把分辨率/编码塞进“主文件名”，可以当作 multi-version label（dash 后）处理，以兼容 Emby 客户端“版本选择”。

### 1.4 Movie Extras（电影花絮/附加内容）

Emby 允许在电影文件夹下使用 `extras/specials/featurettes/interviews/...` 等子目录存放花絮，且强调避免因缺少主电影文件导致误识别。 ([Emby][2])

## 2. Emby 官方：剧集命名（TV Naming）

### 2.1 推荐目录结构：`Series (Year)\Season X\`

Emby 推荐 TV 目录结构为：`Series (year)\Season #\Episode`；并强调每个剧必须有独立的 show folder，年份对 reboot/同名剧极其有帮助。 ([Emby][3])

### 2.2 Episode 命名支持多种模式，但核心是 SxxEyy

Emby 支持多种集号表达（`S01E01`、`1x02`、`102`、甚至 `02 Episode Name.ext`），但实践上最稳的是标准 `SxxEyy`。 ([Emby][3])

### 2.3 Specials（特别篇/OVA/SP）官方处理方式：Season 0 / Specials / Season 00 + S00Eyy

Emby 明确 Specials 文件夹可用：`Season 0`、`Season 00` 或 `Specials`；示例命名为 `S00E01`。 ([Emby][3])
社区回答也强化：Specials 本质是 Season 0，命名形如 `Doctor Who (2005) S00EXX Title`。 ([Emby][4])

> **行业共识**：OVA / SP / 特典 / 特别篇 → **统一落在 Season 00（Specials）并使用 S00Eyy**，这是 Emby/Kodi/Plex 生态里最兼容的方式。

### 2.4 TV Extras（剧集花絮/片段）

Emby 支持在 series/season/episode 层级放 `extras/specials/shorts/scenes/...` 等子目录，并说明某些 extras 不会触发外部元数据匹配。 ([Emby][3])

### 2.5 多版本剧集（Multi-Version Episodes）

Emby 给出“同一集不同版本”的推荐：`show name - S01E01 - Display Name 1.ext`，破折号后的文本用于版本选择显示，且同样有版本数量上限。 ([Emby][3])

## 3. Emby 官方：字幕命名（Subtitles Naming）

Emby 官方明确支持在字幕文件名中标记：

* `.default`：默认字幕
* `.forced` 或 `.foreign`：强制/外语部分字幕
  并给出示例：`Home Alone.spa.default.srt`、`Home Alone.spa.forced.srt` 等。 ([Emby][5])

> **对你的“多语言/字幕处理”关键点**：
> 字幕信息（default/forced）建议体现在字幕文件名而不是视频文件名，以避免视频命名噪音。

此外，Emby.Naming 项目说明其能从字幕文件名解析 language / default / forced 等标记，这意味着“字幕命名规范”在生态内有明确解析链路。 ([GitHub][6])

---

## 4. TMDB 官方：合集（Collection）与元数据接入

TMDB API 官方提供 collection 搜索端点（search collection），并且官方 Getting Started 文档给出 API 的基本使用入口。 ([The Movie Database (TMDB)][7])

> **你要的“自动识别合集”最硬的依据**：
>
> * 对电影：优先使用 TMDB 的 **collection（belongs_to_collection / collection id）** 作为“是否属于合集”的判据
> * 这比“文件夹名相似度/关键词”稳定得多（降低误合并）

## 5. 成熟工具/实现的共同实践（用来对齐“工程可落地”）

### 5.1 FileBot：Specials → Specials folder + S00Eyy 的实践

FileBot 社区/格式表达式示例中明确提到：specials 被组织到 `Specials` 文件夹，命名为 `S00E01` 这种形式。 ([filebot.net][8])

### 5.2 tinyMediaManager：Season 0 与 “Specials” 的等价处理

tinyMediaManager 的设置项中明确提到 Season 0 使用 “Special” 命名（specials 语义），并对 TV renamer 做了专门支持。 ([tinyMediaManager][9])

### 5.3 Emby.Naming：命名解析能力的“参考实现”

Emby.Naming（MediaBrowser/Emby）是一个可测试、无依赖的命名解析库，能力包括：从电影/剧集文件名中提取 name/year/language/quality/episode numbers，并对字幕解析 language/default/forced。 ([GitHub][6])

> **对你的项目意义**：你现在的 parser/judge/renamer 分层很像“工业级”，可以把 Emby.Naming 作为“行为对齐参照”（不是要你直接用，而是对齐其边界与字段）。

## 6. 行业共识总结：你项目应该“冻结”的命名基线

**电影**

* 目录/文件：`Title (Year)/Title (Year).ext` ([Emby][1])
* 可选：`[tmdbid=xxxx]` 写入目录名增强确定性 ([Emby][2])
* 多版本：`Title (Year) - Label.ext`（同目录） ([Emby][2])

**剧集/动画**

* 目录：`Series (Year)/Season 01/`
* 文件：`Series (Year) - S01E01.ext` ([Emby][3])
* 特别篇/OVA/SP：`Season 00` 或 `Specials` + `S00Eyy` ([Emby][3])
* 多版本单集：`Show - S01E01 - Label.ext` ([Emby][3])

**字幕**

* `.default` / `.forced` / `.foreign` 用于外置字幕文件名 ([Emby][5])

**合集（电影 collection）**

* TMDB collection id 作为最可靠的“合集判据” ([The Movie Database (TMDB)][7])
